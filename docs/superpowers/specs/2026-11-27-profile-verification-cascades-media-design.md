# Подтверждение/отклонение анкеты каскадом на её медиа — короткий дизайн

Дата: 2026-11-27 · Размер: небольшое изменение (только фронтенд)

## Зачем
На админском дашборде (колонки очереди модерации) анкета и её файлы модерируются по отдельности:
приняв анкету, админ потом вручную принимает каждое из её фото. Нужно: принял анкету — все её
ожидающие файлы приняты; отклонил — все отклонены.

## Цели / не-цели
- Цель: кнопки «Подтвердить» / «Отклонить» у анкеты в `ModerationQueueBoard` применяют то же решение
  ко всем ожидающим (`moderationStatus = pending`) файлам этой анкеты.
- Не-цель: бэкенд не трогаем (заморожен); Telegram-задачу (claim) не делаем.
- Не-цель: уже принятые/отклонённые файлы не меняем.
- Анти-цель: при отказе по анкете фото не должны оказаться принятыми (и наоборот).

## Подходы
1. **Фронтенд-каскад (выбран).** Сначала `moderateProfileVerification`, после успеха — по каждому
   ожидающему файлу модели из уже загруженной очереди `approveProfileMedia` / `rejectProfileMedia`.
   Без изменений API. Минусы: N запросов, частичный сбой оставит часть файлов в очереди (видно, можно
   доделать вручную); очередь отдаёт ≤200 последних pending-файлов.
2. Каскад в `ModerationService.setProfileVerification` (одна операция на сервере) — надёжнее, но
   требует правки замороженного `apps/api`. Отклонён.

## Дизайн
- Файл: `apps/web/components/ModerationQueueBoard.tsx`, обработчики кнопок анкеты (~стр. 249, 262).
- Порядок: статус анкеты → при успехе файлы. Если бэкенд отказал по анкете (напр. самозарегистрированная
  модель без верификационного фото/видео) — файлы не трогаем, показываем ошибку.
- Набор файлов: `media.filter(m => m.modelId === p.id)` — фото, видео и документы.
- Причина отклонения файлов: «Анкета отклонена».
- Файлы обрабатываются последовательно; ошибки по отдельным файлам собираются, в конце —
  одно сообщение «Не удалось обработать N файлов», затем перезагрузка очереди.
- Если у анкеты есть ожидающие файлы, в карточке показать подсказку вида «+ 10 файлов» рядом с кнопками,
  чтобы админ видел масштаб действия (решение исполнителя; стиль — по `DESIGN.md`/текущей карточке).

## Оставлено исполнителю
Точная разметка подсказки, параллельно/последовательно (дефолт — последовательно), тексты ошибок.
