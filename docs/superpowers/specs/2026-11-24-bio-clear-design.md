# Очистка полей анкеты (био, телефон, WhatsApp, цены) — дизайн

**Дата:** 2026-11-24 · **Ветка:** `fix/bio-edit` · **Размер:** маленькое изменение (3 файла фронта)

## Зачем

Баг: поле заполнено → его очищают → «Сохранить» → «Изменения сохранены», но старое значение возвращается. Сначала просили только био (сделано), затем дали добро на телефон, WhatsApp и цены. Нужно, чтобы пустое значение сохранялось — и из админки, и из «Моей анкеты» модели.

## Причина

- Формы кладут поле в запрос `PUT /models/:id` только если оно непустое (или > 0 для цен).
- Бэкенд (`ModelsService.updateProfile`) обновляет только пришедшие поля → старое значение остаётся.
- Проверено на локальной БД (админ-токен): `{"biography": null}`, `{"rateHourly": null, "rateOvernight": null, "contactPhone": null, "contactWhatsapp": null, "contactTelegram": null}` → все поля `NULL`. Бэкенд менять не нужно.

## Объём

| Поле | Админка: редактирование (`dashboard/models/[id]/edit/page.tsx`, `saveModel`) | Админка: создание — повторное сохранение черновика (`dashboard/models/create/page.tsx`, `buildUpdateBody`) | «Моя анкета» (`model/profile/page.tsx`) |
|---|---|---|---|
| `biography` | ✅ сделано | **чинить** | ✅ сделано |
| `contactPhone` | **чинить** | **чинить** | уже очищается (`v \|\| null`) |
| `contactWhatsapp` | **чинить** | **чинить** | уже очищается |
| `contactTelegram` | **чинить** *(решение ассистента — см. ниже)* | **чинить** | уже очищается |
| `rateHourly` | **чинить** | **чинить** | **чинить** |
| `rateOvernight` | **чинить** | **чинить** | **чинить** |

`buildCreatePayload` (первое создание анкеты) не трогаем — у новой анкеты затирать нечего.

## Не-цели

- slug, физ. параметры («стёрли все разом»), `contactEmail` — не просили.
- Бэкенд — заморожен.

## Подходы

1. **Выбрано: при пустом значении отправлять `null`.** «Нет значения» в БД хранится как `NULL`; так уже работают контакты в «Моей анкете».
2. `""` для текстовых / `0` для цен — отвергнуто: `0` — это «цена 0 ₽», а не «нет цены»; `""` ломает `biography ?? description` (`app/models/[slug]/layout.tsx:19`).
3. Менять бэкенд — отвергнуто.

## Решение

Правило: поле **всегда** отправляется.
- Текст (`biography`, `contactPhone`, `contactWhatsapp`, `contactTelegram`): `value?.trim() || null`.
- Цена (`rateHourly`, `rateOvernight`): значение, если `> 0`, иначе `null`. Формат значения не меняем — где сейчас отправляется число (админка), там число; где строка («Моя анкета», `String(...)`), там строка.

**Решения ассистента (проверить):**
- `contactTelegram` в админке чиним вместе с телефоном и WhatsApp: это один блок «Контакты», тот же баг; иначе Telegram был бы единственным контактом, который нельзя стереть.
- Повторное сохранение черновика на странице создания чиним так же — это та же админка.

Старые строки — закомментировать рядом с пометкой `2026-11-24: пустое значение отправляем null, иначе бэк не очищает поле` (правило проекта: не удалять).

## Проверка

- `npx tsc --noEmit -p apps/web` без ошибок.
- Вручную (локально, :4001, доступы в `DEV-ACCESS.txt`), для каждого поля из таблицы: заполнить → сохранить → стереть → сохранить → перезагрузить: поле пустое, в БД `NULL`; сохранить, не трогая заполненное поле → значение не меняется.
- Публичная страница модели без цены/контактов не показывает «null», «0 ₽» или пустые строки контактов.
