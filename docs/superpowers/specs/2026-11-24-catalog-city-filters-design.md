# Города: фильтр в каталоге + селект в анкете — дизайн

**Дата:** 2026-11-24 · **Ветка:** `feature/filters` · **Размер:** маленькое изменение (4 файла фронта + одна константа, бэкенд не трогаем)

## Зачем

Требование заказчика:

1. В каталоге моделей верхний ряд фильтров заменить на выбор города из фиксированного списка; из панели «Все фильтры» убрать выбор страны/города.
2. В анкете модели (веб-формы) текстовое поле «Город» заменить на селект из того же списка, чтобы город в базе писался ровно так, как его ищет фильтр каталога.

Свободный ввод города остаётся только в Telegram-боте `/newmodel` — это бэкенд, он заморожен.

## Цели

- Верхний ряд каталога: `[Все] [Москва] [Санкт-Петербург] [Казань] [Сочи] · [Все фильтры] [Сбросить фильтры]`.
- «Все» — активна по умолчанию, показывает весь каталог (без параметра `city`).
- Клик по городу показывает только анкеты этого города; пагинация и счётчик корректны.
- Панель «Все фильтры» без блока «Страна / Город»; диапазоны (возраст, рост, вес, грудь, цена) остаются как есть.
- Во всех веб-формах анкеты поле «Город» — селект из тех же 4 городов.
- Один источник списка городов для каталога и форм.

## Не-цели

- Изменения бэкенда (включая Telegram-бота) — бэкенд заморожен.
- Город в URL (`/models?city=…`) — остальные фильтры в URL тоже не хранятся, заказчик не просил.
- Массовая нормализация уже сохранённых значений `city` (например, «СПб»).
- Поле «Страна» в формах — остаётся текстовым, как есть.

## Анти-цели

- Расхождение написаний города между кнопками каталога и селектом в анкете.
- Молчаливая потеря старого значения города при сохранении анкеты.

## Ограничения (как устроено сейчас)

- Город хранится в `model_profiles.physical_attributes` (JSONB), ключ `city`, тип — любая строка (`packages/db/src/schema/model-profiles.ts:84`). Отдельной колонки нет.
- `GET /models?city=X` фильтрует **точным совпадением**: `physical_attributes->>'city' = X` (`apps/api/src/models/models.service.ts:297`). Регистр и пробелы значимы.
- Бэкенд при сохранении анкеты значение не валидирует — список соблюдается только фронтом.
- Telegram-бот (`apps/api/src/bot/model-wizard.service.ts:83`) принимает город свободным текстом. **Принятый риск:** анкета из бота с «СПб»/«москва» не попадёт ни под одну кнопку города (видна под «Все»), пока город не поправят селектом в админке.
- Названия везде точные: «Санкт-Петербург», не «Питер» (решение пользователя).
- В локальной БД (handover-стек) ни у одной из 136 анкет `city` не заполнен — локально любой город в каталоге покажет пустой список; это ожидаемо, не баг.

## Подходы

1. **Выбрано: переиспользовать существующий серверный фильтр + существующий `SelectDropdown`.** В `ModelsClientPage.tsx` уже есть состояние `selectedCity`, которое уходит на бэк параметром `city=`; кнопки городов — существующий `Pill`. В формах — `SelectDropdown`, который уже используется в этих же файлах.
2. Клиентская фильтрация загруженных анкет — отвергнуто (ломает пагинацию).
3. Список городов с бэка (таблица / эндпоинт) — отвергнуто сейчас: бэкенд заморожен; для 4 городов избыточно. Путь миграции: заменить импорт константы на запрос к API, когда бэк разморозят.

## Решения

### Список городов

Новый файл `apps/web/lib/cities.ts`:

```ts
export const CITIES = ['Москва', 'Санкт-Петербург', 'Казань', 'Сочи'] as const;
export type City = (typeof CITIES)[number];
```

Значение = подпись = то, что пишется в базу и уходит в `city=`. Добавить город — правка этого файла и пересборка фронта.

### Каталог — верхний ряд (`apps/web/app/models/ModelsClientPage.tsx`, блок «Filter bar»)

- Закомментировать: пилюли «Все»/«Свободна» по `availabilityStatus`, разделитель, подпись «Сортировка», три пилюли `SORT_OPTIONS`.
- Добавить: `Pill` «Все» (active, когда `selectedCity === ''`) и по `Pill` на каждый город из `CITIES` (active, когда `selectedCity === city`). Клик ставит `selectedCity` и сбрасывает `offset` в 0 — как сейчас `handleLocationSelect`.
- Кнопка переключения вида на мобилке, разделитель, «Все фильтры», «Сбросить фильтры» — без изменений. Подсветка «Все фильтры» больше не зависит от выбранного города/страны.
- Горизонтальный скролл ряда (`overflow-x-auto`, `safe center`) уже есть — «Санкт-Петербург» на мобилке уйдёт в скролл.

### Каталог — панель «Все фильтры» (`FilterPanelContent`)

- **Скрыть** блок «Локация» (два `SelectDropdown`: «Страна», «Город»): закомментировать JSX, пропсы не вырезать.
- Диапазоны, «Сбросить фильтры», «Применить» — без изменений.

### Каталог — поведение по умолчанию

- Сортировка остаётся `rating desc` (текущий дефолт `filters`, параметры продолжают уходить в запрос), просто без UI — заказчик попросил убрать сортировку из интерфейса.
- `availabilityStatus` остаётся пустым — фильтр «Свободна» уходит полностью.
- «Сбросить фильтры» возвращает город на «Все» — `resetAllFilters` уже это делает.

### Анкета — селект города

Три веб-формы, во всех `<input {...register('physicalAttributes.city')}>` → `SelectDropdown` (стиль и размер как у соседних селектов в той же форме):

| Форма | Файл |
|---|---|
| Админка: создание модели | `apps/web/app/dashboard/models/create/page.tsx:1315` (дефолт `'Москва'` остаётся — он в списке) |
| Админка: редактирование | `apps/web/app/dashboard/models/[id]/edit/page.tsx:1264` |
| Кабинет модели «Моя анкета» | `apps/web/app/model/profile/page.tsx:477` |

Опции селекта:

- `''` → «Не указан» (город необязателен — как сейчас в `lib/validations.ts:30`);
- 4 города из `CITIES`;
- **если текущее значение анкеты не из списка** (пришло из бота или старое, например «СПб») — дополнительная опция с этим значением и подписью «СПб (не из списка)». Сохранение без изменений оставляет его как есть; выбор города из списка заменяет. *(Решение ассистента — против анти-цели «молчаливая потеря значения».)*

Поле «Страна» рядом — без изменений (текст).

### Старый код — комментируем, не удаляем

Решение пользователя: ничего не удаляем. Всё, что уходит из UI, **закомментировать** на месте с короткой пометкой причины — по образцу уже закомментированного `LocationSidebar` в этом же файле:

- каталог: пилюли «Все»/«Свободна», подпись «Сортировка», пилюли `SORT_OPTIONS`, блок «Страна / Город» в `FilterPanelContent`;
- формы анкеты: старый `<input {...register('physicalAttributes.city')}>` в каждой из трёх форм (оставить закомментированным рядом с новым селектом).

Логику (`selectedCountry`, `geoModels`, `dynamicGeoData`, `SORT_OPTIONS`, `setSort`, `handleLocationSelect`) и `components/LocationSidebar.tsx` не трогаем. Если lint/tsc ругается на неиспользуемые импорты/переменные — закомментировать их же, а не удалять.

### Параметры запроса каталога

Состав запроса `GET /models` не меняется, кроме `city`: `orderBy=rating&order=desc&limit=15` продолжают уходить из дефолтов `filters`. Без `orderBy` бэкенд сортирует по имени (`models.service.ts:337`), поэтому параметры сортировки **не убирать**, убираются только кнопки.

## Оставлено исполнителю

- Как подключить `SelectDropdown` к react-hook-form (`Controller` или `watch` + `setValue`) — по тому, как это уже сделано для других селектов в каждой форме.
- Точная форма handler-а для кнопок города в каталоге.
- `filters.district` (Москва / МО по районам) в UI не выведена — не трогать.

## Проверка

- `tsc --noEmit` для `apps/web` проходит.
- Каталог (фронт :4001, API в контейнере :4000): ряд показывает нужные кнопки; «Все» активна при открытии; клик по городу шлёт `GET /models?city=<город>&…` (DevTools; локально выдача пустая — в БД нет городов); «Все» убирает `city`; панель «Все фильтры» без страны/города; «Сбросить фильтры» возвращает «Все».
- Формы: в каждой из трёх выбрать город → сохранить → `PATCH`/`POST` уходит с `physicalAttributes.city` ровно из списка; после этого анкета находится кнопкой этого города в каталоге. Анкета со значением не из списка открывается с опцией «… (не из списка)», сохранение без правки значение не теряет.
