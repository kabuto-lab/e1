# Интеграция: Talk-me (онлайн-чат) в NAS

**Что это.** Talk-me — омниканальный онлайн-консультант (чат-виджет на сайт + пульт
оператора + мессенджеры). Для NAS — внешний **канал «Оператор»** (одна из CTA-точек
тенанта). Не заменяет внутренний чат NAS, не касается escrow/денег.

**Источник API** (рендерится в SPA-кабинете Talk-me, смотреть под авторизацией):
- Вебхуки: `https://lcab.talk-me.ru/cabinet/public/documentation/webhook/onlineChat`
- Настройка: ЛК → Мои сайты → (проект) → API → «Webhook-и».
- Виджет: JS-сниппет `window.TalkMe('method', args)`.
- REST: токен проекта (ЛК → API), методы отправки/чтения диалогов — сигнатуры из OpenAPI в ЛК.

---

## Архитектура

```
Посетитель сайта тенанта ──► Talk-me виджет (JS-сниппет на /{tenant})
                                     │
            (новое сообщение) webhook ▼  POST + кастом-заголовок-секрет
                          NAS API: POST /v1/integrations/talk-me/webhook
                                     │  верификация секрета → резолв тенанта → запись лида
                                     ▼
                         таблица лидов/событий NAS  ──►  /admin (входящие)
```

Два направления:
1. **Виджет на сайт** (web → клиент видит чат). Сниппет Talk-me с `id` проекта тенанта.
2. **Webhook в NAS** (Talk-me → наш бэкенд). Событие «новое сообщение от клиента» → лид.

---

## Конфигурация (per-tenant, без новой схемы)

Хранить в `tenants.settings.integrations.talkMe` (jsonb — без миграции):
```jsonc
{
  "talkMe": {
    "enabled": true,
    "widgetId": "<id проекта Talk-me>",   // для JS-сниппета на сайте
    "webhookSecret": "<случайный секрет>", // сверяем в кастом-заголовке вебхука
    "restToken": "<токен проекта>"          // опц., для исходящих ответов через REST
  }
}
```
- `widgetId` отдаётся публично (он и так в HTML сайта).
- `webhookSecret` / `restToken` — секреты, в публичный API тенанта не отдавать (только server-side).

## Этапы

### Фаза 1 — виджет на сайтах тенантов (web, non-spine)
- Компонент `apps/web/src/components/integrations/TalkMeWidget.tsx`:
  загружает `/support/support.js?h=<widgetId>` и инициализирует `window.TalkMe`.
- Подключать в `TenantSiteShell` / bespoke-хоумах (Vanilia/Nebesa/Roxy) при
  `tenant.settings.integrations.talkMe.enabled`.
- CTA-точка «Оператор» (CTA10) при включённом Talk-me открывает чат:
  `TalkMe('openChat')` вместо ссылки.

### Фаза 2 — приём вебхука (api, non-spine)
- `apps/api/src/integrations/talk-me/` — контроллер + сервис:
  - `POST /v1/integrations/talk-me/webhook` — **@SkipTenant()** (внешний вызов; тенанта
    резолвим из payload/секрета), сверка `webhookSecret` из кастом-заголовка;
  - парсинг payload «новое сообщение от клиента» → запись в лиды/события тенанта;
  - идемпотентность по id сообщения.
- Точную форму payload и список событий снять из вебхук-доки в ЛК (раздел §Источник).

### Фаза 3 — лиды в /admin (web)
- Раздел/виджет «Входящие из чата» в админке тенанта (читает лиды Фазы 2).
- Опц.: ответ оператора из NAS через Talk-me REST (`restToken`).

### Фаза 4 (опц.) — хранение в БД
- Если jsonb-настроек/лида-в-логе мало → новая таблица `integration_leads`
  (миграция = **spine**, только с OK оператора; ADR в `docs/DECISIONS.md`).

## Безопасность
- Вебхук-эндпоинт публичный → **обязательна** проверка секрета (кастом-заголовок Talk-me)
  + резолв тенанта; без совпадения — 401, ничего не пишем.
- Секреты только в `tenants.settings` (server-side), не в публичных DTO, не в git.
- Rate-limit на webhook-роут.

## Открытые вопросы (нужен доступ к ЛК Talk-me)
- Точные имена событий и JSON-payload вебхука.
- Формат кастом-заголовка для верификации (имя/значение).
- REST-методы и схема авторизации для исходящих ответов.
