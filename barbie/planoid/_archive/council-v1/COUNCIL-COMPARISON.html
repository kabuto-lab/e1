Barbie · Совет vs «как было» · сравнительные таблицы

Две таблицы. Первая — что меняется в подходе к работе с введением Совета 14-ти умов (governance/ v1.0, 2026-05-26). Вторая — что Совет правит в текущем плане миграции MIGRATION_PLAN_work4u_into_NAS_2026-05-25.md (v1.1) по фазам A–K.
governance v1.0 принят 2026-05-26 визуальное сопровождение к governance/README.md

Совет — это не «новый процесс поверх старого». Существующие практики (ENTITY.md §M режимы, TLA §9, Engineering Entity §11, session-plans, SESSION_LOG, user-level memory) сохраняются как есть. Совет добавляет 14 когнитивных углов к одному и тому же артефакту с обязательным расхождением мнений (Tension Doctrine), детерминированный конфликт-резолвер (Judge), 10 named drift detectors и матрицу активаций — чтобы трудозатраты Совета не появлялись на тривиальных правках.

Для NAS-стека (TS / NestJS / Drizzle / Next.js) сущности перепривязаны под конкретный код: FORGEMASTER думает про N+1 в Drizzle и RSC bundle, не про Arc<Mutex<_>>; SENTINEL ставит tenant-leak первым приоритетом; MIGRATOR владеет WP-import fidelity. Priority Ladder поднимает Maintainability выше Performance — потому что NAS, по ENTITY.md §11, — long-term asset, не hyperscale CMS.

Таблица 1 · Подход — «было» vs «стало с Советом»

Аспект Было Стало с Советом Польза
Архитектурное решение Один TLA-pass (Strategic → Architectural → Implementation, ENTITY §9). Один угол зрения — ассистент сам. TLA остаётся как структура одного решения. Поверх — 14 углов на тот же артефакт: ORCHESTRATOR (эпик), FORGEMASTER (стек), SENTINEL (failure/tenant), SIMPLIFIER (anti-bloat), ECONOMIST (cost) и т.д. Tension Doctrine: согласие на первом проходе подозрительно. Архитектура — не сглаженный single-view, а форсированно противоречивый.
Конфликт мнений Человек резолвит вручную («так лучше, потому что …»). JUDGE §7: детерминированный 8-шаговый алгоритм (restate → Ladder rung → Immutables → Forbiddens → Drift → survivor → measurable count → tie-break to operator). Воспроизводимый разбор. Можно ревизовать verdict на следующем RETRO. Personal-authority overrides запрещены (F-9).
Tenant-leak — главная экзистенциальная угроза NAS «Tenant guard есть в коде». Проверка ручная при code-review. Tenant-isolation specs шипятся после факта (см. коммит 33468af). SENTINEL обязан показать и guard, и WHERE в репозитории, и spec-имя в §Sentinel Risk Audit. Plus drift-детектор D-3 (tenant-guard coverage drift) сметает routes без guard ежедневным sweep T13. Tenant leak — Correctness #1 (Ladder). Защита от регрессии когда новый эндпоинт пропускают мимо ревью.
Перф-утверждение «Это быстрее» / «оптимально» — на словах. ENTITY §11 Engineering Behavior просит измерения, но без обязующего mechanism. F-2 / A-2: каждое perf-claim либо измерено (EXPLAIN / autocannon / Lighthouse), либо тегируется [claim: unmeasured estimate, source: …]. Unmeasured claims, driving a decision, требуют follow-up VAL slot. «Faster» больше не риторика. Если decision принят на unmeasured claim — это видно и обязывает к замеру в следующей сессии.
Drift между сессиями SESSION_LOG + user-level memory ловят то, что вспомнили. Системного детектора нет. 10 named drift patterns (D-1..D-10) с обозначенным детектором и cadence: D-1 scope-creep, D-3 tenant-guard coverage, D-5 migration-state, D-6 planning-trail, D-7 architecture-layer — каждую non-trivial сессию T13. D-2/D-9 — weekly. D-4/D-8/D-10 — epic RETRO. Drift обнаруживается на дне 1, а не на M6. Cadence — фиксирован, не «когда вспомним».
ADR / decision history Commit messages + SESSION_LOG. Контракт неявный, поиск по grep. governance/decision-graph.md — append-only граф ratified / anticipated ADR (Historian Tier-2). F-10: Status: Proposed старше 7 дней — обязательно ratify, supersede или reject. Eternal-WIP запрещён. Контракты явные. Контрадикция новой ADR с ratified отлавливается (D-9).
Cost accounting Считают, когда счёт VPS становится больно. Per-tenant scaling curve не называется. ECONOMIST Ledger обязателен на non-trivial сессии: Δ ₽/month, per-tenant curve (O(1) / O(log N) / O(N)), maintenance cost, cheaper variant considered (yes/no). «Бесконечно-масштабируется» без матмодели запрещено (F-7). Cost-debt не накапливается тихо.
Migration safety «drizzle-kit generate → db:migrate». Rollback — на удачу. MIGRATOR Outlook на каждой миграции: forward-only ✓, expand-contract phase если destructive, rollback test status. CHAOS даёт rollback drill (что если миграция упала на 30 из 57 городов?). I-7 forward-only — Immutable. VPS-сюрприз класса «28P01 / том несовместим» (ENTITY §6) минимизирован — Migrator + Chaos cosign до применения.
Simplification Когда раздражение от bloat накапливается — рефакторят. §2.2 Tension Doctrine: если три Tier-1 согласились с первого захода — SIMPLIFIER обязан попытаться удалить ≥ 1 surface. Не удалит — original стоит; удалит — reduced заменяет. Deletion — глагол, не «когда-нибудь». Speculative scaffolding (F-4) отлавливается на этапе предложения, а не через год.
Failure modes «Должно работать». «Edge case потом». A-5: SENTINEL обязан назвать ≥ 1 concrete failure mode с детектором и recovery — либо escalate to Judge с explicit laziness flag. «No concerns» = review not performed (§2.3). Каждая non-trivial сессия имеет хотя бы один задокументированный отказной режим + plan B.
Новый public endpoint Controller написан, Zod-валидация добавляется, tenant guard «не забываем», rate limit — потом. Activation Matrix §14 row «New public HTTP endpoint»: Tier-1 + ADVERSARY + TEST PILOT обязательны. Adversary гарантирует rate limit + body-size + audit log on 4xx/5xx. Test Pilot — saturation curve. Rate-limit + body-cap mandatory pre-merge, не post-incident. Hot-path saturation known before deploy.
WP-import URL fetch (SSRF риск) «У нас sanitization есть». SSRF allow-list — на ad-hoc усмотрение. ADVERSARY auto-on для любого WP-import code change. ADR-003 (SSRF allow-list policy) уже стоит в decision-graph.md §1 как anticipated; должна ratify до следующей migration-сессии. SSRF — known класс эксплоитов; не «решим если случится». Allow-list policy — единая, codified.
Admin UI consistency «Потом подгоним под dashboard-2077.html». Палитра / scoop / rail / RF Rufo проверяются на глаз. PRODUCTOR verdict на каждой /admin/* сессии: палитра ✓ / scoop ✓ / rail ✓ / RF Rufo ✓, exceptions explicit. ADR-006 (palette compliance check) anticipated — будущий CSS-token snapshot test. I-10 (dashboard-2077 = ground truth) перестаёт быть честным словом; есть верификация и след в session artifact.
AVTONOM accountability SESSION_LOG + memory + AI-Default decisions с обоснованием. Всё перечисленное плюс: §S first-line status mandatory, §A-1..A-10 anti-laziness тесты gate ratification, skipped-pass discipline (§2.6 — implicit skip = malformed session). «Drafted» vs «ratified» — формальная разница. Полу-готовая AVTONOM-сессия не маскируется под завершённую.
Lazy generation «TODO: позже» / «TBD» в коде и доках допустимо. F-11: TBD/TODO/«fill in later» в ratified артефакте запрещены. Drafts могут — ratification требует resolution или explicit deferral в follow-up slot. Скрытые контракты не накапливаются. «Невидимый долг» (F-3 hidden re-litigation) ловится Historian.
Plan vs reality drift Надежда + ручная сверка с blueprint. D-1 scope creep — каждый T13 sweep сверяет git diff --stat со scope сессии-плана. D-8 forecast drift — каждый epic RETRO сверяет §entering state vs реальность. Drift ловится в днях, не в M6+. Перекладка плана в monthly RETRO — формализованная процедура (через MPD-аналог Motion).
Тривиальная правка Same workflow что и для нового модуля — overhead на каждый коммит. Activation Matrix §14 row 1 (trivial fix): Tier-1 verdict only; T2–T10 explicitly skipped с reason. Full Council pass на typo = F-1 consensus theater. Overhead Совета ≈ 0 на однострочных правках. Полная глубина — только когда стоит.
